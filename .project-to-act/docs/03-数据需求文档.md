## 1. 工厂采集规范 V1（面向工厂人员）

交付原则：**一文件一主题、编码稳定唯一、数值带单位、日期 `YYYY-MM-DD`、空值留空、
每表填资料日期/编制人/审核人/版本**。命名如 `BOM_P-USB-C-001_A_20260905.xlsx`。

### 四类主资料

1. **BOM**：主表（产品编码/BOM 版本/生效日期）+ 明细表（物料编码/名称/单台用量/
   单位/损耗率/替代料/位置号）。
2. **SOP/工艺**：工艺路线主表（产品/路线码/版本/审批状态）+ SOP 工序表（工序号/
   名称/标准工时【**IE 标准工时必填正数并注明口径**】/设备/工位/人员技能/换型时间）；
   另附换型/首件 IE 明细表。
3. **工程图**：清单（图号/版本/关联产品/关键特性/变更说明），**须附 ECN**。
4. **库存**：快照主表（快照时间/仓库）+ 按物料批次/库位明细（现存/可用/锁定/
   QC 状态/批次号/入库时间）。

### 配套主数据

机器可用信息、模治具台账、人员工资（**敏感信息单独加密传送，原始身份证/银行卡/
工资不得直接上传**）、产品计件工资、物料主数据、供应商、工位、班次日历。

## 2. 内部数据规范（冻结基线）

四个 canonical schema：`m0.bom.v1`、`m0.route.v1`（standard_minutes/station_code/
equipment_codes）、`m0.drawing.v1`、`m0.inventory.v1`（available+locked 不得大于
on_hand；无快照时间/批次只能为候选）。

**一切事实必须带共同元数据**：`tenant_id、task_id、source_filename、source_sha256、
source_system、observed_at、schema_version、revision、effective_from/to、evidence_ref、
approval_status、idempotency_key`。

规则：文件上传成功 ≠ 事实可用；模型推断必须标 `inferred=true`；未审批提取只能是
candidate；工程图几何语义不能仅凭解析器确认；工资数据不能证明排程能力。

**建议交付数据格式**（8 组）：station_master、worker 主数据+资格、equipment_+日历、
approved_route、order_lines、inventory/open_po/wip snapshot、production_unit_mapping、
execution_events.jsonl，附统一元数据列。

## 3. PMC 生产放行的数据缺口（P0 阻断，两次独立审计一致确认）

以下均**无可用实体数据**，是真实 PMC 排程的硬阻断：

| 缺口 | 影响 |
|---|---|
| 人员主数据与技能资格 | 无法人员绑定 |
| 人员-工位绑定 | solver blocked |
| 生产班次日历 | 无法排班 |
| 批准路线版本（现有 SOP 为 USB-C demo，与 HDMI 订单不匹配） | 工序事实不可用 |
| 设备能力/状态 | 无法设备绑定 |
| 当前 WIP | 排程初值缺失 |
| 物料批次 QC / PO ETA | 供应事实缺失 |
| 生产单元映射 | 工位分组缺失 |
| MES 执行回传 | 执行闭环缺失 |

实测例证：真实订单 PO-20260812-001（8 行 47000 件）经 PMC v2 展开 94 个
transfer batch 后因缺工位/人员绑定 `solver_status=blocked`；W-H909 复验 14 道工序
**全部缺 IE 标准工时**（standard_minutes_missing=14）。

**补齐前，真实 PMC 只能标记"候选/草稿/数据阻断"，禁止生产放行
（production_blocked=false 不得验收）。**

## 4. 数据现状盘点（2026-09-04 审计）

- **业务目录候选库**（yunpai-business-catalog.sqlite）：441 个来源文件
  （订单 218 / 采购 70 / BOM 39 / 工程文档 39 / 工程图 24 / SOP 21-22 / 库存 7），
  绝大多数为 candidate/unclassified，**approved=0**——候选 ≠ canonical 主数据。
- **M0 canonical 对账结论**：canonical 表存在但 approved_candidates=0；
  committed 批次的 master_counts 全 0；legacy data_import_commit 映射待治理
  （W-H909 commit 返回 success 但回读 0——发布闭环遗留问题）。
- **微信/本机资料审计**：真实原始资料大量存在但分散半结构化——订单（桐曦等）、
  手工排产/生产日报、`中性系列-成品BOM表-2026.04.28.xlsx`、库存、SOP（HDTV/光纤
  作业指导书约 15 个工站页**含 IE 秒数**）、设备/模具清单、供应商/采购入库、押出部
  约 18 条工资记录。未找到：全厂人员主表与技能资格、人员-工位绑定、班次日历、
  稳定 station_id、批次级 WIP、设备维护历史、批准路线版本、MES 执行事件。
- 补传 M0 建议顺序：物料/产品/BOM/route → 设备模具 → 供应商采购库存 → 人员技能班次
  → 日历WIP/MES → 成本财务。
