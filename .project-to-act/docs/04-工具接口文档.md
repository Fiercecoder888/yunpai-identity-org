## 2. 各模块核心契约要点

### M0（默认 http://m0:8010，本地 m0_backend）
- 导入七层：`data_import_run`（POST /api/m0/import/upload）→ status → preview →
  resolve → **commit** → rollback → history/quarantine；commit 前必须 resolve。
- canonical 发布：`data_catalog_ingest_validate/publish` + 九类 import facade
  （products/orders/boms/materials/suppliers/equipment/routes/operations/tooling），
  PostgreSQL 单事务 + Outbox，120s 超时。
- 查询：`get_m0_product_overview/graph`、`list_m0_documents`、`list_m0_inventory`。
- 发布成功判据：回读 approved_candidates/ledger_count/outbox_count 非零——
  HTTP 200 不等于落库成功（fail-closed 校验）。

### M1（默认 http://m1:8080）
- `ingest_document`：POST /ingest/sync，240s，multipart（不发 base64）；可能 202+
  poll_url（按 `M1_POLL_BUDGET_S=90` 有界轮询，202 绝不当完成）。
- 产出 `m1.document.v2`：SHA-256、MIME、源坐标、parser/model 版本、置信度、证据引用；
  缺字段留空+issue，不填 0/默认值。
- 其余：任务/批次/文档查询、`search_m1_orders`（支持 interface/length/color/connector/
  conductor/od 过滤）、`export_m1_order`（XLSX 四 Sheet）、`submit_m1_review`、
  Governed Wiki 五查询（只返回 active/approved；图和搜索是投影不成 canonical）。
- 跨租户查询返回 404 不泄露存在性；租户缺失 fail-closed（MISSING_TENANT）。

### M2（默认 http://m2:8765）
- `run_bom_sop_workflow`：POST /api/run，300s；输出 draft_created/
  human_input_required、bom_generation、sop_generation、open_customer_questions。
- 端点不可用（HTTP_UNAVAILABLE/TIMEOUT）由编排器转为可恢复 BLOCKED_INPUT 数据 Gate。

### M3（默认 http://m3:8000）
- 正式入口 `run_m3_procurement_requirements`：库存/在途由 Provider 自查（旧兼容入参
  被忽略）；**要求 inventory[*].received_at 必填**。
- `receive_m3_material_demand`：M5 反馈幂等受理。
- 缺料公式：`gross=order_qty×qty_per×(1+loss)`，`shortage=max(0,gross−available)`。

### M4（默认 http://m4:8000）
- 链路：建议导入（json 版需 tenant+site+idempotency_key）→ 生成 PO →
  submit-review / approve / request-changes（**均需 expected_revision+
  expected_checksum，CAS**）→ 邮件草稿 → 供应商回复 parse/confirm → tracking/
  alerts/催单/供应快照（`query_m4_material_supply_snapshot`，无权威时 received/open/
  ETA 为 null）。
- 认证：服务 JWT（M4_AUTHORIZATION / M4_SUPPLY_TOKEN），M3/M4 也可用 M*_API_KEY。

### M5（默认 http://m5-api:8000）
- `solve_scheduling`：幂等键 + expected_head_plan_version；pressure_only 不得发布；
  source_observed_at 逐来源 24h 新鲜度校验；缺事实 BLOCKED_INPUT 不补默认。
- `replan_scheduling` 从服务端版本恢复（parent 保留）；`dispatch` 仅 released
  （无 MES sender 只回 pending）；`report_workload`（event_type: actual_start/
  actual_finish/quantity_report/scrap/exception，数量单位校验通过才计入 PMC，
  **必须调用、不得谎称已记录**）；`bind_worker_to_order`。
- report_workload 与 bind_worker_to_order 未纳入默认绑定（无历史实现）。

## 3. 编排 API（api.py）

`/health`、`/tools`、`/skills`、`POST /runs`、`POST /runs/stream`（NDJSON：
run_start/assistant_delta/step_start/step_result/gate_opened/run_error/run_done）、
`POST /runs/upload`（XLSX 订单）、`GET /runs`、`GET /runs/{id}`、
`POST /runs/{id}/resume`、`POST /runs/{id}/resume/stream`。

- resume decision：`approve | allow | continue | retry | reject | stop`。
- 快照返回时 content_b64 替换为 `[omitted]`。
- `YUNPAI_REQUIRE_TRUSTED_PRINCIPAL=1` 时 resume 缺受信头直接 403。

## 4. 前端对接契约（yunpaizhisuan-FE）

- **原始文件上传必须发 `workflow: "m1_m5_document_to_plan"`**（`m0_m5` 是订单已入库
  后直接排程，其 M1 读 request.document 单数且跑在 M0 之后；发错导致 M1 415）。
- local 模式（`VITE_LOCAL_LANGGRAPH=true`）走 `/runs/stream` + `/runs/{id}/resume/stream`，
  NDJSON 事件与后端 graph.stream 一一对应。
- `documents` 附件数组每项必须带 `kind: "order"`（bridge_payload 按 item.kind=="order"
  取订单附件）；其余字段 filename/content_type/content_b64。
- FE 包缺 `dev/chatHistoryMiddleware`（仅 MSW demo 调用，real 模式不调用），本地构建
  用 no-op 桩占位。
- FE 测试守卫：构建产物不得泄漏任何私网 IP 字面量（businessTrackingAsset.test.ts）。
