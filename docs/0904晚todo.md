# 0904 晚间 TODO

> 目标：围绕 HF 反馈，确认产品与关联数据、最小业务链路、Skill/Tool 完整度，以及前后端联调条件。所有结论都要有代码、数据库、测试或接口证据；没有真实回读证据时，不标记为生产完成。

## 1. 按 HF 反馈核对数据库中的产品与关联关系

- [ ] 盘点产品、订单行、物料、BOM、路线、工序、设备、工位、人员/技能、供应商、库存和 WIP 的实际表/字段/来源。
- [ ] 对每个产品确认：产品编码是否稳定、是否有有效版本、是否关联批准 BOM、工艺路线和订单行。
- [ ] 对每条关键关系确认方向、基数、版本、生效时间、来源证据和审核状态；重点检查产品 -> BOM -> 物料、产品 -> 路线 -> 工序 -> 资源。
- [ ] 区分候选 SQLite、运行库和 M0 PostgreSQL canonical，不能把 `unclassified` 候选或测试快照当作生产主数据。
- [ ] 输出缺口清单：缺表、缺字段、孤儿关系、重复编码、未审核关系和无法回读的外部数据。

**完成标准**：形成一份带实体/关系/证据的核对表；每个关键产品都能明确标记为“已关联、待审核或缺失”。

## 2. 验证最小流程是否能跑通

- [ ] 选择一条最小真实流程：上传资料 -> 识别/分类 -> 候选审核 -> M0 canonical 发布 -> 读取产品/BOM/路线 -> 生成最小计划 -> Gate/结果回读。
- [ ] 使用固定 `task_id`、`run_id`、`snapshot_id` 和来源 checksum，验证重试幂等、状态持久化、`pending_gate` 和 trace 是否连续。
- [ ] 验证缺少产品关系、资源或日历时返回明确的 `BLOCKED_INPUT`，不得静默填默认值。
- [ ] 记录每一步的接口、数据库写入/回读、审批点、错误信息和测试证据。

**完成标准**：最小流程在本地测试环境可重复跑通；若被 39092/M0 外部条件阻塞，记录阻塞接口和解除条件，不宣称生产验收通过。

## 3. 大 Skill 功能自查

- [ ] 逐项对照大 Skill 的合同、输入输出、权限/租户上下文、异常处理、证据和持久化要求。
- [ ] 检查 Skill 是否真正绑定到 registry/handler，是否存在只声明未实现、实现未注册或返回结构不一致。
- [ ] 为大 Skill 的每个子功能补一条成功路径、一条参数/数据缺失路径和一条外部依赖失败路径测试。
- [ ] 核对大 Skill 各子功能之间的上下游字段、版本和 snapshot 约束，避免单项通过但组合链路断裂。

**完成标准**：得到大 Skill 覆盖矩阵，列出已通过、仅本地 fixture、依赖外部服务和待修复项。

## 4. Tool 补全与修复

- [ ] 按 manifest/registry 逐个核对工具数量、名称、绑定 handler、输入 schema、输出 schema 和错误码。
- [ ] 优先修复最小流程所需工具，再处理边界工具；补齐异步任务、HTTP 调用、租户头、超时、重试、幂等和审计字段。
- [ ] 删除或阻止未绑定工具的假成功结果；外部服务不可达时返回可诊断错误并保留 trace。
- [ ] 为新增/修复工具补单元测试和 registry 数量/绑定状态断言。

**完成标准**：工具合同与实现一致，注册表可验证，相关后端测试通过；外部 HTTP/数据库联调仍需单独标注。

## 5. 与前端联合验证

- [ ] 和前端逐项对齐接口字段、状态枚举、Gate/审批交互、错误展示和长任务轮询/流式更新。
- [ ] 用真实后端响应验证上传、候选审核、发布、最小计划结果和阻塞态，而不是只依赖 mock/fixture。
- [ ] 验证桌面与移动视口的关键操作、刷新恢复、重复提交、失败重试和结果回读。
- [ ] 汇总前后端联调问题，明确责任模块、复现步骤、接口证据和下一修复提交。

**完成标准**：前端可完成最小流程的关键点击和状态闭环；无法联调的部分写明缺失服务、URL、权限或数据条件。

## 晚间交付物与记录

- [ ] 数据库产品/关系核对表及缺口清单。
- [ ] 最小流程运行记录（含 `task_id`/`run_id`/`snapshot_id`、日志和回读证据）。
- [ ] 大 Skill 覆盖矩阵、Tool 修复清单和测试结果。
- [ ] 前后端联调问题单与阻塞项。
- [ ] 更新项目账本中的进度、验收证据和未解除阻塞；未通过的测试或未完成的外部联调必须如实保留。
